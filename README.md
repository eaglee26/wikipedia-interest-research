# wikipedia-interest-research

> An [Agent Skill](https://agentskills.io/specification) that researches how interest in topics changes across
> Wikipedia language editions (Wikimedia Pageviews API) to help B2C founders choose the next topic, course or
> localization language. Docs below are in Ukrainian; `SKILL.md` and `references/` (read by the agent) are in English.

Навичка для AI-агента, яка допомагає засновникам B2C-продуктів вирішувати, **які теми розвивати далі та
якими мовами запускати продукт**, на основі статистики переглядів Вікіпедії. Агент отримує питання
користувача, запускає код навички й відповідає цифрами з явним рівнем довіри та обмеженнями. За потреби
він також робить графіки й PDF-звіт на одну сторінку.

Приклади звітів із реальних даних лежать у [`examples/`](examples/).

## Як це працює

Головна ідея: **чим дешевша модель, тим більше рішень має бути зашито в код, а не в інструкції.**
Код робить усю роботу з даними й судження, які легко зробити неправильно. Агент (навіть Claude Haiku)
перекладає питання в одну команду, читає короткий підсумок і переказує його.

| Крок | Робить код (`scripts/`) | Робить агент (`SKILL.md`) |
|---|---|---|
| Тема → статті | Wikidata: те саме поняття в кожній мові; рейтинг кандидатів за кількістю мовних версій; неоднозначність («Mercury»), покриття, замінники для відсутніх статей | обирає 1–6 понять, підтверджує значення |
| Дані | денні перегляди людей (`agent=user`), SQLite-кеш, ліміти й повтори, User-Agent за політикою Wikimedia, редиректи перейменованих статей | — |
| Аналіз | частка теми в трафіку свого мовного розділу, зміна «12 міс. проти попередніх 12», сезонний тест Кендалла, сплески, вік статей, ширина кошика → рівень довіри HIGH/MEDIUM/LOW з причинами; рейтинг мов із вагами | — |
| Результат | компактний підсумок (~40 рядків), PNG-графіки, PDF на 1 сторінку, перевірка чисел у тексті | пише відповідь і 4 короткі тексти для PDF |

```
wikipedia-interest-research/
├── SKILL.md                 ← інструкція для агента (107 рядків)
├── scripts/wiki.py          ← єдина точка входу (CLI), залежності оголошені в самому файлі (PEP 723)
├── scripts/wikitrends/      ← net, resolve, cache, fetch, stats, analyze, charts, report, textcheck, runs
├── references/              ← методологія, інтерпретація, нотатки про API (агент читає за потреби)
├── assets/                  ← шаблон тексту звіту, відомі «зломи» в даних Wikimedia
├── tests/                   ← 64 тести без мережі на реальних відповідях API
├── evals/                   ← сценарії, раннер для Claude Code / OpenCode, автоматичне оцінювання, результати
└── examples/                ← PDF і графіки з реальних прогонів
```

## Встановлення та запуск

Потрібні Python 3.10+ і доступ до wikimedia.org / wikidata.org. Найпростіше запускати через
[uv](https://docs.astral.sh/uv/): він сам поставить залежності (numpy, matplotlib, certifi). Точні
версії зафіксовано в `uv.lock`.

```bash
# підключити навичку до агента (Claude Code, OpenCode та ін. читають .claude/skills/)
mkdir -p .claude/skills && cp -r /path/to/wikipedia-interest-research .claude/skills/

# перевірити середовище
uv run .claude/skills/wikipedia-interest-research/scripts/wiki.py doctor
```

Без uv: `python3 -m pip install -r requirements.txt`, потім `python3 scripts/wiki.py ...`.

Далі агенту достатньо звичайного питання, наприклад: «Чи зростає інтерес до астрономії в україномовній
Вікіпедії, і наскільки цьому можна довіряти?». Команди можна запускати й вручну:

```bash
uv run scripts/wiki.py research --topics "astronomy, Solar System, black hole" --langs uk --period 36m --ui uk
uv run scripts/wiki.py report --run latest --narrative narrative.json --ui uk   # PDF
uv run scripts/wiki.py check --run latest --text answer.md                    # звірка чисел у тексті
uv run scripts/wiki.py runs                                                   # попередні запуски
uv run scripts/wiki.py diff <run_a> <run_b>                                   # що змінилося після уточнення
```

## Що навичка знаходить на прикладах із завдання

Живі прогони 27.09.2026:

1. **Інтервальне голодування, pl vs cs.** У польській Вікіпедії статті **немає**: поняття Q1666254 не має
   польської сторінки. Навичка каже це прямо, не вигадує цифр і пропонує позначений замінник («піст»,
   Q44602). У чеській: ~183 перегляди/міс, частка −47% за рік, довіра середня через малий трафік.
2. **Астрономія, uk.** Кошик із 5 статей, ~6 800 переглядів/міс. Частка −34%, жоден із 12 місяців не
   кращий за рік тому, довіра висока. Видно шкільну сезонність (піки у вересні та взимку).
3. **Вивчення англійської, 5 мов.** Рейтинг vi > tr > id > pl > uk: у в'єтнамській і турецькій інтерес
   стабільний, у решти падає.

## Як навичка допомагає оцінювати й перевіряти висновки

- **Нормалізація.** Людський трафік Вікіпедії падає: Wikimedia повідомила про ~8% у 2025 році. Тому
  інтерес оцінюється за часткою в трафіку свого мовного розділу, а сирі перегляди показують розмір
  аудиторії.
- **Рівень довіри за прозорими правилами** з причинами простими словами: обсяг, сплески, вік статей,
  ширина кошика, узгодженість місяців, сезонний тест. Опис — у [`references/methodology.md`](references/methodology.md).
- **`CHECK BEFORE ANSWERING`** на початку виводу: неоднозначні теми, відсутні статті, замінники.
- **`wiki.py check` / `report`** звіряють кожне число в тексті агента з результатами. Якщо число
  вигадане, PDF не збирається. Саме це спіймало вигадане Haiku «11,2 млн».
- **Повторні й пов'язані запити.** Кеш (повторний запуск не робить жодного запиту), журнал запусків
  (`runs`), порівняння запусків (`diff`), таблиця «що змінити» в `SKILL.md`.

## Перевірка на дешевих моделях

Кожен сценарій проганяється в чистій папці через справжній агентний клієнт; оцінювання автоматичне
(`evals/grade.py`). 7 сценаріїв: три приклади із завдання, ланцюжок уточнень із PDF, неоднозначна тема,
розмовний запит англійською і запит, де навичка не має вмикатися.

| Ітерація | Модель | З навичкою | Без навички | Час / сценарій | Вартість / сценарій |
|---|---|---|---|---|---|
| 1 | Claude Haiku 4.5 (Claude Code) | 94,6% | 43,5% | 40 с | $0,06 |
| 2 (після виправлень) | Claude Haiku 4.5 (Claude Code) | **100%** | — | 45 с | $0,08 |
| 3–4 | Qwen 3.8 27B `:free` (OpenCode + OpenRouter), 3 сценарії | 82,6% → **96%** (100% після виправлення хибного спрацьовування перевірки) | — | ~2 хв | $0 |

Що змінилося між ітераціями, описано в [`DEVLOG.md`](DEVLOG.md). Відтворити:

```bash
uv run python evals/run_evals.py --harness claude --model haiku --baseline
uv run python evals/run_evals.py --harness opencode --model openrouter/qwen/qwen3.8-27b:free --cases if-pl-cs,astronomy-uk,casual-yoga-en
```

Для OpenRouter потрібен ключ (`opencode auth login`) і поповнення рахунку на $10. Без нього безкоштовні
моделі мають ліміт 50 запитів на день. Самі `:free`-запити гроші не списують.

## Тести

```bash
python3 -m unittest discover -s tests
```

64 тести, мережа не потрібна. Вони використовують реальні відповіді API, збережені у `tests/fixtures/`.
Реалізації статистичних тестів звірено з `scipy` (розбіжність < 1e-10). Лінтер `ruff` і перевірка типів
`pyright` проходять без помилок.
