# ROADMAP: ітеративний розвиток навички

## Принцип

Кожна ітерація проходить той самий цикл:

1. Спостереження: провалена перевірка в evals, помилка в живому прогоні або відгук користувача.
2. Гіпотеза, чому так сталося.
3. Мінімальна зміна. Спершу в коді; в інструкції — лише якщо кодом не вирішується.
4. Тест на цю зміну.
5. Повторний прогін evals на дешевій моделі й порівняння з попередньою ітерацією (`evals/results/`).

Зміна приймається, лише якщо pass rate не падає в жодному сценарії. Причина: `SKILL.md` читає дешева
модель, і кожне нове речення може зламати поведінку в іншому місці.

## Наступні ітерації

### v0.2: надійність відповіді агента (найближче)

- **Перевірка «мова ≠ країна» в коді.** `wiki.py check` попереджає про назви країн і прапори поруч із
  кодами мов. Це єдина помилка Haiku, яка ще трапляється.
- **3 прогони на сценарій** і середнє з розкидом. Один прогін не відрізняє покращення від випадковості.
- **Ширший набір безкоштовних моделей** (OpenRouter free): таблиця «модель → pass rate». Мета —
  визначити мінімальну модель, з якою навичка стабільно працює.
- Сценарії на помилки: мережа недоступна, тема не існує, 10+ мов.

### v0.3: корисніші висновки для засновника

- **Порівняння з еталоном.** Інтерес до теми відносно схожих тем у тій самій мові («астрономія
  проти фізики й біології»), а не лише відносно всього трафіку.
- **Прогноз на 6–12 місяців** з інтервалом (сезонна декомпозиція), чітко позначений як екстраполяція.
- **Оцінка розміру ринку мови**: трафік мовного розділу поряд із трафіком теми, щоб «vi зростає»
  одразу мало масштаб.
- Пошук пов'язаних тем, що зростають (сусіди за Wikidata), як відповідь на «що ще варто дослідити?».

### v0.4: інші джерела й формати

- Розбивка за пристроями (мобільний / десктоп) як окремий сигнал для мобільних застосунків.
- Кілька тем в одному звіті (2 сторінки), CSV-експорт для таблиць.
- Опційно: Google Trends як друге незалежне джерело для перехресної перевірки (окремий модуль,
  вимкнений за замовчуванням, щоб не додавати залежностей).

## Як додати ітерацію

```bash
python3 -m unittest discover -s tests                     # 1. тести
uv run python evals/run_evals.py --harness claude --model haiku   # 2. evals → evals/results/iter-*.json
```

Потім дописати рядок у таблицю результатів у `DEVLOG.md`: що змінилося, яка перевірка покращилася.
